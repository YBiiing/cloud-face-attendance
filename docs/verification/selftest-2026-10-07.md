## 环境和验证边界

Windows、Docker Desktop、MySQL 8.4、Redis、Celery 和真实 buffalo_l CPU 模型。所有测试数据和故障注入均使用 `face-attendance-test` 项目、`face_attendance_test` 数据库和 localhost:8001；开发项目未进行故障注入。

Android Emulator 37.2.12，Pixel 6a、Android 15/API 35、Chrome，2 GB 虚拟内存、2 个 CPU 核心。模拟器通过 `http://10.0.2.2:8001` 访问测试 API。截图由安卓设备截图命令获得，不是桌面浏览器的手机尺寸模拟。

虚拟相机阶段改为 3 GB 内存，并仅在该次启动参数中将前摄设为 AI 图片源、后摄设为 emulated；没有使用物理 webcam。2 GB 的相机返回出现 Chrome 内存不足提示，3 GB 下 JPEG 能返回并上传。默认启动脚本和 AVD 配置未因此修改。

模拟器默认时区与宿主机不同，因此截图里的课程本地时间不能直接与文档的 Asia/Shanghai 日期比较。业务时间仍按接口的 UTC 时间和服务器接收时间校验。

没有使用真人照片。前一阶段的空白 PNG、无脸界面截图仅能验证 NO_FACE。后一阶段使用内置 imagegen 生成的完全虚构人像，真实运行模型检测、512 维编码与检索，没有替换模型输出或调整阈值。它能验证合成样本链路，不能代表真人准确率或真人验收。Playwright WebKit 是 Windows 上的浏览器引擎测试，不是 iPhone 或 iOS Simulator。

## 发现的问题与建议

1. **老师缺少匿名签到链接入口（P2）**。`web/assets/sessions.js` 只创建“查看出勤名单”和“提前结束”按钮；后端仍返回 checkin_path。学生登录后可以找到场次，但未录入人员无法登录取得链接。`docs/week3-submission.md` 的“复制该场次签到链接”已与现界面不符。建议在老师场次卡片增加打开/复制匿名签到链接，学生原有待签到列表保持可用。
2. **手机上传结果不够醒目（P2）**。安卓选图后，图片预览使提交按钮和其后的结果提示落到屏幕下方；NO_FACE 返回时未主动滚动到提示，需再向下滚动才看到完整反馈。建议将处理结果置于当前可见位置，或在终态提示后滚动到结果；同时保留状态播报。注册页也有同类现象。
3. **依赖故障响应有明显等待（待优化）**。API 的 Redis 客户端设置 2 秒连接/读写超时，但安装的 redis-py 6.4.0 默认重试 3 次；实测就绪失败耗时约 8 秒。MySQL 就绪失败也约 8 秒。当前仍返回正确降级结果，没有证据证明存活接口被阻塞。建议明确整体故障响应预算，并为就绪探测和交互请求配置受控重试。
4. **MySQL 不可用的业务接口返回 500（P2）**。班级接口在数据库停止时返回 INTERNAL_ERROR/500，正文没有泄露 SQL 或凭据，但与依赖不可用返回 503 的约定不一致。建议针对可识别的数据库连接异常统一降级响应，继续隐藏底层异常信息。
5. **换照片后沿用旧结果（P2）**。安卓上 A 签到成功后选择未录入 B，预览已经是 B，底部仍显示“签到成功”；再次提交才变成正确拒绝。`checkin.js` 的 input 事件更新幂等键但未清除旧结果，可能让下一位误以为已经完成。建议照片变化后清除旧结果或显示“照片已更换，请提交”。证据：[换图后的旧提示](selftest-2026-10-07/android-ai-stale-feedback.png)。
6. **共享网络出口的签到容量约束（待明确）**。匿名签到按来源 IP 固定每 60 秒最多 30 次提交，实测第 31 次返回 429，没有 Retry-After。一个班的多台设备若共享校园网 NAT，可能共同触发此限制。此测试证明限流生效，不证明每名学生都拥有 30 次独立额度。建议按课堂规模明确匿名防滥用及峰值接收策略，再验证共享出口场景；不宜直接取消防护。
7. **认证照片上传连接池相互等待（P1）**。真实 HTTP 10 并发照片库上传出现 8 个 INTERNAL_ERROR/500，日志耗时约 5 秒。`current_user` 通过 yield 型 `db_session` 查询并一直持有连接；异步 `add_face` 又在线程里调用 `face_transaction`，新开 Session 申请第二个连接。池配置为 pool_size=5、max_overflow=5、pool_timeout=5，总共仅 10 个连接。10 个请求各占鉴权连接时，事务无法取得额外连接。用测试屏障固定这个交错后，10 个请求全部出现已捕获的 QueuePool TimeoutError。优先消除跨阶段的连接持有/重复事务占用，保证鉴权与提交的权限校验仍有效；单纯扩大连接池会推迟相同问题的出现。证据：[原始 HTTP 日志/数据库核验](selftest-2026-10-07/queue-failed-results.json)、[受控诊断](selftest-2026-10-07/pool-diagnostic-results.json)。
