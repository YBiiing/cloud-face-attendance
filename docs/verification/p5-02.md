# P5-02 识别与签到事务

`attendance_records` 通过场次与人员唯一约束防重复，通过复合外键保证人员属于冻结名单。worker 在事务外提取特征、检索全体有效人员；完成事务按照特征库版本 → 任务 → 场次 → 人员锁顺序，验证版本、执行尝试、截止时间、用户状态和名单，原子保存记录与任务结果。

特征库变化时最多重查三次；截止前完整接收的照片允许截止后完成。超时或旧执行尝试不能写记录。终态签到任务释放 Redis 配额，异常未释放的配额到期后由下一次入队清理。

MySQL 集成验证 4 项：两个线程同人同场次最多一条记录，重放不改首次时间；不同场次各有记录；旧尝试与超时拒绝；库版本变化要求重算；注入事务异常后记录和任务一起回滚；未知、相似身份与名单外人员拒绝；匿名 HTTP 到 worker 到记录的完整业务路径；真实 Celery/ONNX 无脸图片拒绝。

正向身份匹配使用明示的合成特征，不能替代真人测试。`MATCH_THRESHOLD=0.5`、`MATCH_MARGIN=0.05` 是可配置开发初值，尚未由真人样本校准，不声明准确率。
