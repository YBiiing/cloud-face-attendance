## 实际执行结果

- 重新构建测试镜像后执行 `docker compose -p face-attendance-test -f compose.yaml -f compose.test.yaml run --rm tests`：**43 passed，2 warnings，19.63 秒**。警告来自 Starlette/httpx 与 InsightFace/skimage 的弃用提示。
- 恢复扫描验证投递失败补投、15 秒发布租约、执行租约过期、最多三次执行、旧尝试失效以及提交后重复投递。MySQL 1205/1213 最多在新事务中重试三次，其他数据库错误不盲目重试。
- Linux 子进程运行实际 worker 函数，在提取与写入前主动退出；测试将租约改为过期，再由真实 Celery 和 ONNX 完成 NO_FACE。提交后的子进程退出与重复投递没有重复执行。此测试没有覆盖直接杀死 Celery prefork 子进程的全部确认时序。
- 单独执行 `scripts/test_redis_recovery.py`：停止隔离测试 Redis，确认投递失败，恢复 Redis 后补投成功。未停止开发环境 Redis。
- 照片清理测试保留有效标准照、活动任务、近期文件和非托管文件，只清理满足保留期的托管文件；验证照片停用后旧识别结果不能写入签到记录。未对开发资料执行清理。
- 备份验证拒绝覆盖、非空目标、非测试环境和不安全 ZIP 路径。在全新 `face-attendance-restore` 数据卷迁移后恢复 **14 行、1 张照片**；逐表比较所有数据、照片 SHA256、2048 字节特征及向量范数通过。使用的是合成测试特征，不能证明真人模型匹配效果。
- 恢复环境显式复制本地缓存 buffalo_l 权重，模型 CPU 加载成功；启动 API/worker/scheduler 后 ready 的 MySQL、Redis、model_worker 均正常；`alembic check` 无差异。这是全新数据卷复现，不是全新操作系统安装验证。
- 独立分档压测详见 [负载记录](local-load.md)。保留限流，30 个已接收请求全部完成 NO_FACE，6 个请求返回 429。
