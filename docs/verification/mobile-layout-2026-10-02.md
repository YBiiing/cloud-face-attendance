# 手机端布局修正

日期：2026-10-02。此前布局主要依靠缩窄桌面页面及自动换行，本轮改为手机优先布局。

## 改动

- 学生三项、老师四项底部导航；账户标识与退出移到顶部，桌面仍使用普通横向导航。
- 适配顶部刘海和底部安全区，页面底部保留导航空间；输入表单时隐藏底栏，并等本次指针点击结束再恢复，避免挡住提交按钮。
- 手机使用单列输入、通栏主要按钮、至少 44px 导航和 48px 操作按钮；输入字号不少于 16px，避免常见的输入缩放问题。
- 相册与拍照并排显示为 52px 触控区域，隐藏占空间的原生文件输入外观，同时保留原生文件选择与键盘可访问性。
- 减少表单嵌套留白；日期输入限制容器宽度，长文本换行，预览图限制高度，分页采用稳定的三列布局。

## 验证

Edge 触摸/移动模式下运行完整角色流程：320×568、390×844、430×932、844×390 横屏，以及 1280×800 桌面宽度。五档均通过。断言包括无横向溢出、输入字体至少 16px、底栏位置、导航触控高度、底部预留空间、输入时隐藏/失焦恢复，以及实际从输入框点击发布按钮可跳转。

390 宽度首次发现底栏在焦点变化时重新出现，干扰发布按钮点击；修正指针期间的恢复时机后，390 与 320 重测通过，再验证 430、横屏和桌面通过。

原注册恢复、签到/记录、前次审查修复三个浏览器脚本也通过。本轮只改前端，未重跑后端数据库测试。浏览器 API 为测试夹具，无真实人脸或开发资料写入。

```powershell
.\.venv\Scripts\python.exe tests/browser/check_hci_flow.py --width 390 --height 844 --output docs/verification/mobile-2026-10-02/390
```
