## 实际执行

在仓库根目录运行，Docker 使用独立 `face-attendance-test` 项目、数据库和数据卷：

```powershell
docker compose -p face-attendance-test -f compose.yaml -f compose.test.yaml build tests migrate
docker compose -p face-attendance-test -f compose.yaml -f compose.test.yaml run --rm tests
.\.venv\Scripts\python.exe tests/browser/check_registration.py
.\.venv\Scripts\python.exe tests/browser/check_attendance.py
.\.venv\Scripts\python.exe tests/browser/check_review_fixes.py
```

- 完整后端回归：**58 passed，2 warnings，23.07 秒**。两条警告为已有 Starlette/httpx 和 InsightFace/skimage 弃用提示。
- 三个浏览器脚本全部通过：注册中断恢复、签到与记录既有流程、审查问题回归。
- 先前浏览器脚本将 404 当作临时网络错误；本轮改为连续 503 验证临时故障，并新增持续 404 的失效分支测试。浏览器夹具仅缩短轮询等待，生产页面的超时与退避设置未缩短。
- 混合容量测试首次因测试学号超出 32 字符而返回 422；缩短测试标识后按原容量断言通过，未修改业务校验。

## 证据限制与使用说明

提交确认丢失测试为“真实数据库提交后注入客户端异常”，不是实际网络断线实验。浏览器使用本地静态页面和 mock API，页面恢复为事件模拟，不代替真实手机 BFCache、弱网或人脸识别验收。响应性用例验证事件循环可继续工作，不提供新的吞吐量承诺。

备份恢复在 COMMIT 开始后发生异常时可能留下已恢复资料；应保留现场、核查数据库结果，不手动清空照片后直接重试。需要重新恢复时使用新的隔离目标。提交前的写入失败仍回滚并清理本次创建的文件。

真人录入、同人异照识别、未录入真人拒识及手机拍照仍由手动验收对话继续；云部署按既定顺序最后实施。
